## A『小雨の予報』— int じゃなくて ll

**1 日目の降水量 A から、毎日 B ずつ増える N 日分を出力する**。**等差数列を並べるだけ**の問題です。

それなのに **ペナルティ 169**。理由を **frostflower さん** が一行で教えてくれています：

{{< twitter user="frostflower_753" id="2117588779779371013" >}}

> #AWC0192 **A intじゃなくてllでやりましょうね** B そのまま C 優先度キューを使って{点,-idx}で順に番号をつけていく D 難易度順にソートし,優先度キュー使って得点が高いK個を保持していく E [left,right]で必要な数を区間スケジューリングで求めて{未使用端,使った個数}をDPしようとしたが6WAが取れず

**「int じゃなくて ll でやりましょうね」** 💧 **N 日目の降水量は A + (N−1)B**。**制約によっては 32 ビット整数の範囲を超える**ので、**`int` で計算すると溢れて WA**になります。**200 点の A で、これほど多くの人がつまずいた**のは珍しいですね。

**☆ありゅ☆ さん**：**`[A + n * B for n in range(N)]` を出力**、**YTOK\_cp さん**：**「a を出力して a += b」を n 回**。**Python や Julia なら気にしなくてよい**ところです。

**B は「面積がいちばん大きい畑（同じなら番号の小さい方）」**。**☆ありゅ☆ さん** の **`dat.index(max(dat)) + 1`**、**YTOK\_cp さん** の **「a\*b の argmax」**。**ペナ 42** も、**A × B の積の大きさ**が効いたのかもしれません。

## D『コンテストの準備』— 上位 K 問を保ち続ける

**K 問を選んで配点の合計を P 以上にしたい。そのとき、選んだ問題の難易度の最大値を最小化**。

**難易度の低い順に問題を見ていき、「配点の大きい K 問」を優先度付きキューで保ち続ける**。**その和が初めて P 以上になったときの難易度**が答えです。

**frostflower さん**：**「難易度順にソートし, 優先度キュー使って得点が高い K 個を保持していく」**、**ぴよ さん**：**「難易度の低い問題から順に、点数が高い K 問分だけ保持するバイナリーヒープに放り込んでいっていつ条件を満たすかサーチした」**、**YTOK\_cp さん**：**「(難易度昇順、配点降順) でソートして MinHeap につっこむ」**。

**二分探索派**もいました。**ごりちゃん さん**：**「難易度の最大値でにぶたん」**、**yamate11 さん**：**「難易度の順に配点をみていって，みたうちの大きい方から K 個の和が P 以上になったときの難易度，ではダメなのかな．二分探索に直して通ったけれど．」** — **ヒープの方針でも正しいはず**ですが、**どこかで WA が出て二分探索に切り替えた**ようです。

**micci さん** の **「DP ぽいと思ったが N も P も大きい。二分探索や尺取りを考えたが分からず」** は、**惜しいところまで来ていた**のが伝わります。
