## A『色紙の正方形』と B『壁の塗装』

**A は (A / C) × (B / C)**。**「割ってから掛ける」の順番**が大事で、**sorachandu さん**：**「A\*B/(C\*C) と勘違いして落ちました (懺悔)」**、**frostflower さん**：**「(a/c)\*(b/c), 括弧なくてペナ」** 📄 **A·B / C² は「余りの部分をつなげて数えてしまう」**ので、**縦と横でそれぞれ切り捨てる**必要がありました。

**B は幅 K のローラーで障害物のないマスをすべて塗る最小回数**。**ランレングス圧縮して、「.」の連続ごとに ⌈長さ / K⌉ を足す**、**長さが K 未満の区間があれば −1** です。**☆ありゅ☆ さん**：**「S.split("#") して 0 超過 K 未満の要素があれば -1」**、**YTOK\_cp さん**：**「文字列を split して length するとやりやすい定期」**、**うにだよ さん** と **だれおん さん**：**「RLE」**。

## C『りんご狩りの最適プラン』— 最大部分和

**A\_i − C を並べた列の最大部分和**（空も可なので 0 以上）です 🍎

**yamate11 さん**：**「A[i] - C の累積和を B, B の累積最小値を C として，B - C の最大値」**、**YTOK\_cp さん**：**「max\_i(x\_i-min(x\_1,...,x\_{i-1})) 典型」**、**うにだよ さん**：**「dp[i+1]=max(dp[i]+A[i]-C, A[i]-C)」**、**ぴよ さん**：**「順に足していってハイスコアをチェックするだけ（ただし、足していく途中でマイナスになったらゼロにリセット）」**。**累積和の差**でも、**DP（Kadane のアルゴリズム）**でも書ける、典型の一問でした。

## D『魚捕り』— W × H の網

**W × H の長方形の網を 1 回置いて、捕まえられる魚の最大数**。**N ≤ 3000** なので、**網の端を魚の座標に合わせる候補を全探索**して数えます 🐟

**☆ありゅ☆ さん**：**「座標圧縮して縦方向と横方向で尺取法」**、**だれおん さん**：**「X を尺取してその中で Y の尺取」**、**うにだよ さん**：**「端の Y 座標全部試して X 座標で尺取」**、**frostflower さん**：**「x 軸尺取しながら seg 木で y 軸の数を得る」**、**yamate11 さん**：**「座標圧縮して 2 次元累積和」**。

**計算量の見積もり**で悔しい思いをした人も。**yamate11 さん**：**「横着して X と Y の座標圧縮を共通にしたら TLE だった．6000^2 は 3000^2 の 4 倍大きいからなあ．」**、**sorachandu さん**：**「Rectangle Sum でよいですね！ → Dynamic Point Add しか持ってなくて TLE」**、**ぴよ さん**：**「座標圧縮＋平面の累積和でいけるとおもったがちがうみたいだ orz」**。

## E『スタンプラリー』— 左右に行き来する区間 DP

**数直線上のチェックポイントを、期限 T\_i までに通過してスタンプを集める**。**0 から左右に広がっていくので、「訪れた区間 [l, r]・今どちらの端にいるか・獲得数」を状態にした区間 DP**が定石です。**AC 20** の難問でした 🗺️

**kwm\_t さん**：**「これ好き。 dp[l][r][右 or 左][獲得数]=経過時刻で区間 dp」**、**うにだよ さん**：**「正の座標を i 個目まで、負の座標を j 個目まで、取得したチェックポイントが k 個のときの最小タイムで DP したら嘘か更新順がダメだったからダイクストラしたら通った」**。

**つつじ さん**：**「1 回往の全探索かと思いましたが、もっと細かく折り返す必要があることに気が付きませんでした」**、**だれおん さん**：**「時間が小さい方からの dp をしていくとダメで右左を行き来する dp を書きたいがわからん」**、**TakaakiUmedu さん**：**「DP テーブルが多重過ぎてデバッグが面倒くさい…」**、**YTOK\_cp さん**：**「DP[到達した区間左端, 右端, 今左端か右端か, 獲得数] で時間を最小化 時間切」** — **状態まで見えていても、時間内に書き切るのが難しい**問題でした。
