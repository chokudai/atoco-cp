## D『リレー配送と日替わり手数料』— 読解の D

**D の問題文は 5 問中いちばん長く**、**配達員・担当件数の範囲 L\_j ≤ k ≤ R\_j・費用 A\_j(X\_{j+k} − X\_j) + B\_j・日ごとの追加手数料 C\_q** と、**登場する要素が多い**問題でした。

参加者の第一声は、ほぼこれです。

**うにだよ さん**：**「難読すぎる」**、**amesyu さん**：**「D は読解の D！」**、**ウルズニャー さん**：**「D キチィ！！！！」**、**riki さん**：**「読解が面倒なので愚直に dp やったら TLE」**

{{< twitter user="amesyu2" id="2107440770286579880" >}}

> #AWC0172 全 A: mod 24 B: count C: 隣接だけかい！均した結果平均未満かと勘違い **D: Dは読解のD！dp[i][k] = [0,i)まででk人使った時の解を求めるとN^3で、クエリでN使うのでO(N^3 + NQ)** E: Range Set QueryをWavelet Matrixで解くやつに帰着

読み解いてしまえば、鍵は一つでした。**日ごとに変わるのは「1 人起用するたびの手数料 C\_q」だけ**。だから **「何人使ったか」ごとに、手数料抜きの最小費用を前計算**しておけば、**各日は「人数 × C\_q」を足して最小を取るだけ**になります。

**yamate11 さん** の書き方がいちばん明快です：**「dp[i][j] = (届け先 i まで j 人使って配送するコストの最小値)．配る DP で O(N^3) で埋められる．クエリ q では，min\_i (dp[N][i] + i \* C[q]) を答える．」**

**riki さん** は TLE からここにたどり着いています：**「愚直に dp やったら TLE、どこを減らせるか見たら人数持てば良い」**

届かなかった方も。**ぴよ さん**：**「D：TLE がでるんだけど。。。ふつうに DP やるだけじゃだめなんだろうか？」**、**つつじ さん**：**「D は、DP で解こうとして、方針は合ってそうでしたが、答えが全く合いませんでした。」** — **日ごとに DP をやり直すと、Q が最大 20 万なので間に合わない**。**「人数」という軸を足すのが、この問題のひと工夫**でした。

## E『山道の展望ポイント』— 解き方が 6 通り

**区間 [L, R] を左から歩いて、それまでの最高を真に超えた地点の数を数える**。区間クエリが最大 20 万個です。

**D と AC 数がほぼ同じ E** ですが、**解き方がこれほど分かれた問題も珍しい**です。

**① ダブリング** — **うにだよ さん**：**「地点 i より右にあって A\_i より大きい値で最初に出てくる地点を求める、ダブリングで i の 2^j 次の地点を求める 長さ m を二分探索で地点 i の m 個先が r 以下か」**

**② スタック + セグ木（オフライン）** — **riki さん**：**「L で降順に見て stack で単調増加を維持してセグ木で R までカウント」**

**③ Wavelet Matrix** — **amesyu さん**：**「Range Set Query を Wavelet Matrix で解くやつに帰着」**

**④ 平方分割** — **Tanaka.A さん**：**「平方分割して、各ブロックで見える順を事前計算し、そこまでの最大高さで二分探索しながらカウント」**

**⑤ Mo's algorithm** — **Takaaki Umedu さん**：

> #AtCoder #AWC0172 **ギリギリ残り50秒でEだけ。** まずはこの方法でデータを前処理して、クエリ毎にあの方法で集計すれば求まるはず、の前半も後半も色々勘違いしててドタバタ(笑)。**特に後半は結局、必殺Moを繰り出すまでに大混乱。** こんなややこしくなくても解けそうな気がしてしょうがない…
