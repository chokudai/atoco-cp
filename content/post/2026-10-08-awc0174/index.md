## A『駅に間に合う』— 配点 166 点

ここで **YTOK\_cp さん** が、**Julia での味わい深い落とし穴**を報告しています：

> B: all(any(nextC()=='o' for _ in 1:w) for _ in 1:h) ってやるとshort-circuitingで読み込みがズレるという味わい深さがある

**`any` が途中で true を見つけると、残りの文字を読まずに次の行へ進んでしまう** — **入力を読みながら判定すると、読み残しのぶんだけ次の行がずれる**わけです 📖 **短絡評価そのものは便利**なのに、**読み込みと組み合わせると罠になる**。**YTOK\_cp さん** は本番では **「all(any(==('o'),[nextC() for _ in 1:w]) for _ in 1:h)」** と、**先に配列として読み切る**形で通しています。

## C『ペアでぴったり』— 「相方を見てから、自分を数える」

**友達 N 人のスコアから、合計がちょうど K になるペア (i, j) を数える**。

## E『括弧列とスタックオーバーフロー』— 答えの種類は O(√N)

**括弧列を左から読み、スタックサイズが T 以上になったらクラッシュして空に戻る。閾値 T ごとに、クラッシュの合計回数を答える**。クエリは最大 20 万個です。

**AC 11 名**。通した人の説明を見ると、**鍵は「答えの種類が少ない」こと**でした。

**𡆢 さん**：

{{< twitter user="0x3b800001" id="2108165528510501295" >}}

> #AWC0174 お疲れ様でした. 1 位！ A ✓ FA. T+D/V B ✓ FA. yesno S.all? { _1 =~ /o/ } C ✓ Hash で DP D ✓ FA. だいくすとら法 **E ✓ FA. 答えの種類数が O(√N) なので答えが等しい最大の T を二分探索で求め、あとなんかいいかんじにすることで O(Q logQ + N √N logN) になる**

**うにだよ さん** が、その理由を書いています：**「スタックサイズ T のクラッシュ回数は最大 floor(N/T) 回 サイズ 1~√N は普通に答えを求める √N より大きいもののクラッシュ回数は 1~√N 回くらいなので、クラッシュ回数ごとに許容される最小サイズを二分探索で求める」**（続けて **「1~ ではなくクラッシュ回数 0 回もある」** と補足）

**1 回クラッシュするには T 文字以上読む必要がある**ので、**クラッシュ回数は N / T 回以下**。**T が小さいときは T そのものが √N 通りしかなく**、**T が大きいときはクラッシュ回数が √N 通りしかない**。**どちらの場合も「種類」は √N 程度**、というわけです ✨

**YTOK\_cp さん** は別の道を試していました：**「(min,max) を管理するセグ木で max\_right しながらメモ化したら調和級数で間に合う？WA で終わった」**。**Takaaki Umedu さん** は **「ダメ元って程でもなさそうなので真面目にデバッグしてみて、やっぱり合わせられず時間切れ」**。**もぐら 2.0 さん** の **「E はじっくりと読んだものの、問題の意味が理解できず・・・」**、**秋ナス さん** の **「難しい😢」** も、この E の手強さを物語っています。
