## A『AtCoder Reverse Contest』— 「ARC」を並べて数を作る構築

**AC 率 36%**。**「文字列中の A と C のペアの個数を X ちょうどにする」** 構築問題で、**タイトルどおり ARC を並べる**のが基本形でした。

**かびぽよ さん** の説明が簡潔：

{{< twitter user="kabipoyo" id="2096240188129476856" >}}

> A. **ARAR...CRCR... で 25×25 = 625 回 までできる。これを 625−X 回 swap して出力。**言われたらそうなんだけど**思いつくのが難しい**

**「A を 25 個、C を 25 個 → 積で 625 通りまで作れる → そこから差分だけ swap」** という、**上限から引き算する**発想。

**おっちゃん さん**：

{{< twitter user="occhan_code" id="2096240100703399961" >}}

> A: **A25 個 C25 個置いて隙間に R を置けば 625 回も swap できる**

**あてむ さん**：**「A: A25 個 C24 個 + R を並べるとちょうど 600 回 swap できるので、必要な数 swap しておく」**

**dokukuma さん** はより直接的な構築：

{{< twitter user="dokukumao" id="2096240035083460872" >}}

> A: ARARA...RCRCR を作る．**A を 25 個置くとして，AR.. を X%25 個置いた後 RC を置き，最後に RC を X/25 個置く**

**「X を 25 で割った商と余りに分解して配置」** — 割り算で直接構築するルートです。

{{< twitter user="gkms_knsr" id="2096238214399111645" >}}

**「AR を X 個並べる素朴解 → 長さ制限 100 に引っかかる → 効率化が必要」** という思考の流れが、対話で綺麗に示されています。**長さ制限が本質**だったわけですね。
