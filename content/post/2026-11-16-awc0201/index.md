## A『給料と返済』と B『折れたネガ』

**A は A 円の借金を B 円ずつ返す回数 = ⌈A / B⌉**。**☆ありゅ☆ さん** の **`(A + B-1) // B`**、**YTOK\_cp さん** の **「div\_ceil 定番」**。**TakaakiUmedu さん** は **「ループで、と思ったら制約が A の癖にでかくてあやうく TLE になりかけるという引っかけ問題」** 💴 — **A ≤ 10^9、B = 1 なら 10^9 回**のループになります。

## C『水の流れ』— 1 だけ残して下流へ（ペナ 67）

**タンク i のバルブを開けると、水の半分（切り捨て）が i + 1 へ流れる**。**何度でも開けられる**ので、**2 以上入っている限り開け続ければ、最後に 1 だけ残して残りを下流へ送れます**。**上から順にシミュレーション**すると、**1 つのタンクで開ける回数は log A\_i 回程度**で間に合います 💧

**とーらす さん**：**「開閉を繰り返すと 1 だけ残して右に流せる」**、**Tanaka.A さん**：**「2 以上残っている限り A[i]/2 を下流に送る」**、**遠宮歩 さん**：**「上からシミュレーションすれば Nlog(max(A)) で間に合う」**、**𡆢 さん**：**「愚直にやってもどうせ O(NlogA)」**。

**ペナ 67 の理由の一つ**を、**YTOK\_cp さん** が書いています：**「1 を残して次に渡せるけど A\_i = 0 がコーナーケース」**。**「各タンクに 1 残る」と決め打って A\_i − 1 を送ると、もともと 0 のタンクで −1 になってしまう**わけですね。**秋ナス さん** の **「後ろからやらなくていいのは分かってない」**のように、**処理の向き**で迷った人もいました。

## D『アイテムの整理』— 個数と価値の DP

**ちょうど K 個を手放して、残りの価値の合計が X 以上になる選び方を数える**。**「何個手放したか」と「残した価値の合計」を状態にした DP** です。**A\_i ≤ 50、N ≤ 100** なので、**価値の合計は最大 5000** に収まります 📦

**とーらす さん**：**「dp[ 見た個数 ][ 捨てた個数 ][ 価値合計 ] := # ways で DP して集計」**、**ぴよ さん**：**「DP[アイテム番号][手元に残したアイテム数][価値合計]」**、**Tanaka.A さん**：**「個数×価値で DP」**、**☆ありゅ☆ さん**：**「dp[(個数, 価値)] = 何通り の dict」**。**遠宮歩 さん** の **「D は DP の D」** 😄

## E『荷物の運搬』— bitset の部分和

**荷物を 2 人に分けて、重さの差の最小値を求める**。**作れる重さの集合（部分和）が分かれば、合計の半分にいちばん近いものを選ぶ**だけ。**合計 ≤ 10^5、N ≤ 10^5** なので、**普通の DP（N × 合計）では 10^10 で間に合わず、bitset で 64 倍速くする**のが鍵でした 🧳

**yamate11 さん**：**「制約を見ずに普通に DP をして (おかしいと思えよ) TLE．bitset に直して通した．」**、**Tanaka.A さん**：**「あり得る重さ総和をビット化して 64 倍高速化 DP」**、**遠宮歩 さん**：**「初めて bitset 高速化を使えて嬉しい」**、**とーらす さん**：**「bitset でもつやつを多倍長で」**、**☆ありゅ☆ さん**：**`dp = (dp | (dp << a))`**。

**Python では整数そのものを bitset として使える**のがポイントで、**まえすとろ さん** の **「Python の bitset って普通に int で対応すればよかったんか....C++ とか Rust で書いているみたいに 64 word で割るとかせんでもええやん。。。」** がそれを物語っています。

**別の道**もありました。**𡆢 さん** は **「多項式を優先度付きキューにぶち込んで次数小さい順に畳込みした」**、**YTOK\_cp さん** は **「n≥10^3 くらいなら重さの重複が多いはず…」** と、**同じ重さが多いことを使う方向**を考えています。
