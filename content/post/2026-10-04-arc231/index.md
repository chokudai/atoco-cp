## A『Two Dimensional Invader』— N² から落とせるか

**モンスターを剣で倒すと、そこまで移動して「距離の 2 乗」のコスト。魔法で倒すとコスト Z\_i で移動なし**。最小コストを求めます。

**素朴な DP は「どこにいるか」を持って O(N²)**。ここで止まった人がとても多かったです。

**ぜりとき さん**：**「N^2 からどうやって落とすの？」**、**ごりちゃん さん**：**「素朴な dp しか見えず、解けなかった これ早くなるの...？」**、**(np)↑2🚰 さん**：**「N^2 から落とせず 嘘 DP で WA」**、**ニホニエル さん**：**「グラフ作ろうとしたが明らかに O(N^2) なので無理」**、**ミカン小僧 さん**：**「ユークリッド距離が求められません」**

鍵は **「距離の 2 乗 = x 方向の 2 乗 + y 方向の 2 乗」に分けられること**と、**座標が 500 未満と小さいこと**でした。**くで さん** が丁寧に書いています：

{{< twitter user="kude_coder" id="2106748206017347873" >}}

> ARC231 **A:dp[i][j]=座標(i,j)にいるときの最小コスト とするDPを高速化。ユークリッド距離の移動を2段階で処理。1段階目は「貰う」と考えてx座標移動を処理。2段階目は「配る」と考えてy座標移動を処理。** 全体+zしたくなるので、最後に全体+Σzをするよう調整。 B:X,Yに[0,A),[0,B)は必須。Zに[0,C)を含

**このしろ さん**：**「遷移の距離が x 方向と y 方向に分離できることを利用し、片方の最小値を前計算して O(500N) に高速化する」**、**くすにぬ さん**：**「縦横のコストは分離できるので、行ごとに列ごとのコストをもつ」**、**カリア さん**：**「x 軸と y 軸のコストを別々に管理する」**

**yuma さん** の **「寄与を縦横に分けて処理できることに気付くのが遅すぎた JOI::Maze の気持ち」** も同じ発想ですね。**🤜io🤛 さん** は **「放物線の convex hull trick」**、**Segtree さん** は **「クエリ平方分割」+ CHT** と、**別の高速化**で挑んだ方もいました。

**Cafe1942 さん** は A に時間を使いすぎたことを悔やんでいます：**「A の DP のデータ構造こねこね(失敗)に時間かけてなければ、C 流石に間に合ってたと思うんだけど… A も B も何もわからず、どこが 500 点やねんというお気持ちになってる。」**

## B『Three Mex』— 「1024」というギャグ

**mex(X) = A、mex(Y) = B、X と Y の全ペアの XOR の集合 Z について mex(Z) = C、となる集合を作れ**。要素は 2026 以下、A, B, C は 1000 以下。

**この「1000 以下」と「2026 以下」が答えでした**。**sig さん** の一言がすべてを言っています：**「1024+1000 <= 2026 です…」**

**カリア さん**：

{{< twitter user="kaliafluorido" id="2106748007765139798" >}}

> ARC231、２完 A：x軸とy軸のコストを別々に管理する。dp[x][y]をyを固定してxに移動するときのコストの最小値とする **B：ギャグ。Xは[0,a)と1024とYは[0,b)と1024^i (0<=i<c)**

**「B：ギャグ」** 😂 **X に [0, A) と 1024、Y に [0, B) と 1024 ⊕ i** を入れると、**1024 ⊕ (1024 ⊕ i) = i** で **好きな i を Z に足せる**。**1024 は A, B, C のどれよりも大きい 2 のべき**なので、**mex(X) や mex(Y) を壊さない**というわけです。

**yamate11 さん** が条件まで含めて書いています：**「X, Y に 0,..., A - 1 と 0, ..., B - 1 を入れる．この時点で，Z の mex が C より大きくなっていたら不可．そうでなければ，X に 1024 を，Y に 1024 から 1024 + C - 1 までを入れる．」**

**river0525 さん** は **「入力が 1000 以下で集合が 2026 以下という条件に着目する。この二つを 2 進数表記すると、1000|2\*\*10<=2026 だと分かる」**、**harel さん** は **「A,B,C が 1000 以下を見て 1024 使えば自由に数字作れそうだなで AC」**、**ミカン小僧 さん** は **「1024 を使って構成」**、**🤜io🤛 さん** は **「制約でメタ読み」** 🔍 **制約から答えが透けて見える**タイプの問題でした。

ただし **思いつかないと永遠に見えない**のもギャグ問題の怖さです。**yuma さん**：**「ギャグに敗北...」**、**ぜりとき さん**：**「適当な貪欲は通らない。一瞬 SAT に見えたがそんなことはない」**、**ウルズニャー さん**：**「B は何も浮かばないけど、貪欲通るんじゃね？をやったら 2WA で殺してくれ。」**

**あてむ さん** は **「2 進数で先頭の桁をそろえたら行けそう…」** と **2 進数の方向までは来ていた**のに、**「A=0 のパターンで全く合わず。実装こんなややこしいなら想定解な訳ないんだよな」**。**harel さん** の **「開始 5 分後に見たときに mex と xor が見えて無理そうだなって思って A に戻ってしまったのが悔やまれる」** も、**B を後回しにした人の多さ**を物語っています。

**セック さん** の **「B 解けたから最悪は免れたものの他はさっぱりわからん…」** に頷いた方も多いはずです。今夜の **「B 1 完」は立派な結果**でした 🌸

## E『Odd Inversion』と F『Two Unbalanced Subtrees』

**E は「1 ≤ B\_i ≤ A\_i で、転倒数が奇数になる列 B を数える」**。**AC 174 名・ペナ 18**。

**Segtree さん**：**「転倒数が偶数のものと奇数のものでペアを作る」**、**yuma さん**：**「swap である程度一対一対応させるやつだが、いい対応が分からず...」** — **偶数と奇数を組にして打ち消し、組にならない部分だけを数える**方向のようです。**くすにぬ さん** は **「結構通されてるので見たものの、解けず」**、**ニホニエル さん** は **「転倒に関する問題は無理」**。

**F は完全二分木の頂点に 1 〜 2^N - 1 を書き、各頂点の値が「左右の部分木の総和の差」になるようにする構築**。**根の値を最小化**します。**AC 39 名**。

**全完した 鳳。 さん** の言葉が印象的です：

{{< twitter user="AmGinE_8" id="2106748453019881972" >}}

> #ARC231 **勝ったからいいけどギャグだろ** F:子の部分木の総和は片方が親の半分になるようにすることを考えると、根が1段深くなるごとに2の指数が小さくなるように構成するのが良さそうだと感じられる すると頂点1に書く値が2\*\*(n-2)に決まり、何故か絶対値の差を親直下の子2つで処理するといい感じになる

**「勝ったからいいけどギャグだろ」** — **B に続いて F もギャグ**という評価です 😄 **「何故か絶対値の差を親直下の子 2 つで処理するといい感じになる」** と、**通した本人も「何故か」と書いている**のが ARC の F らしいですね。
